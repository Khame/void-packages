Khame XBPS repository

Signed x86_64 packages for Void Linux, built for runit (no systemd). Everything is published for glibc; kxbps is published for x86_64-musl as well.

Packages

  • asusctl — ASUS ROG control daemon and CLI tools, with an optional KDE Plasma widget in asusctl-plasma. Documentation: Khame/asusctl-void-linux
  • doublecmd — twin-panel (commander-style) file manager, built from source with Void's FPC/Lazarus. Documentation: Khame/doublecmd-void-linux
  • kxbps — native KDE Plasma front end for the xbps package manager: package table, update checks, queue and plan. Documentation: Khame/kxbps
  • rivalcfg — SteelSeries mouse configuration CLI, patched to use system udev rules and the plugdev group. Documentation: Khame/rivalcfg-void-linux
  • sensei310-tray — KDE tray controller for the SteelSeries Sensei 310, with guided button mapping. Documentation: Khame/sensei310-tray

Usage

sudo sh -c 'echo "repository=https://khame.github.io/void-packages/" > /etc/xbps.d/10-khame.conf'
sudo xbps-install -S      # answer Y to import the repository key
sudo xbps-install asusctl doublecmd kxbps sensei310-tray

rivalcfg is installed as a dependency of sensei310-tray. asusctl-plasma is the optional Plasma widget for asusctl.

On an x86_64-musl system the repository line names the musl tree, which carries the same key and kxbps alone:

sudo sh -c 'echo "repository=https://khame.github.io/void-packages/musl/" > /etc/xbps.d/10-khame.conf'
sudo xbps-install -S
sudo xbps-install kxbps

Signing key

Packages are RSA-signed. The key is embedded in the repository index and imported by xbps automatically; Khame-void-repo.pub is published for manual verification. Unsigned installation is not supported.
